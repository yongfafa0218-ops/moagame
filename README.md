# 모아 — 우리끼리 게임 한 판

각자 아이폰·안드로이드에서 5~6명이 함께하는 온라인 보드게임 웹앱입니다. GitHub에 올리고 Netlify에 연결할 수 있도록 만들었습니다. **앱 코드에는 광고, 코인, 인앱 결제, 회원가입이 없습니다.** 인터넷 연결은 필요합니다.

> 이것은 정식 루미큐브·카탄 앱이 아닌, 익숙한 규칙을 참고한 독립 구현입니다. 다른 판본과 차이가 있는 부분은 아래에 적었습니다. 실제 Netlify 계정에는 아직 배포하지 않았으니 배포 후 휴대폰 두 대 이상으로 꼭 확인해 주세요.

## 1. GitHub에 올리기

컴퓨터에서 작업하는 편이 쉽습니다.

1. 전달받은 ZIP을 풀고 `moa-netlify` 폴더를 엽니다. 안에 `netlify.toml`, `package.json`, `public`, `netlify`, `server` 등이 바로 보여야 합니다.
2. GitHub에 로그인하고 새 저장소(repository)를 만듭니다. 개인적으로 쓰려면 **Private** 저장소를 권장합니다.
3. 저장소에서 **Add file → Upload files**를 선택합니다. 빈 저장소에서는 **uploading an existing file** 링크가 보일 수 있습니다.
4. 압축을 푼 **폴더 자체가 아니라 그 안의 내용물 전체**를 선택해 업로드합니다. `netlify.toml`과 `package.json`이 저장소 첫 화면에 보이게 하는 것이 중요합니다. `public` 등 하위 폴더도 빠짐없이 올립니다. 숨김 파일인 `.gitignore`는 보이지 않으면 생략해도 배포에는 지장이 없습니다.
5. **Commit changes**를 누릅니다. ZIP 파일을 그대로 올리는 것이 아닙니다.

[GitHub 파일 업로드 공식 안내](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)

## 2. Netlify에 연결하기

1. Netlify에 로그인하고 팀의 **Add new project → Import an existing project**를 누릅니다.
2. GitHub를 선택하고, 요청이 나오면 방금 만든 저장소에 대한 접근을 허용합니다. 해당 저장소를 선택합니다.
3. 대부분 `netlify.toml` 설정이 자동 적용됩니다. 화면에서 확인이 필요하면 다음과 같습니다.
   - Base directory: **비워 두기**
   - Build command: `npm run build`
   - Publish directory: `public`
   - Node 버전: **22** (`netlify.toml`에 지정됨)
   - Functions directory: `netlify/functions` (`netlify.toml`에 지정됨)
4. **Deploy/Publish**를 누르고 배포가 성공할 때까지 기다립니다. `https://...netlify.app` 주소가 생깁니다. 별도의 서버나 API 키는 넣지 않습니다. Netlify Functions와 Netlify Blobs는 해당 사이트에서 사용할 수 있어야 합니다.
5. 친구가 로그인 없이 접속하려면 Netlify 프로젝트가 **Public**이어야 합니다. 새 팀은 Private으로 시작할 수 있습니다. 필요한 경우 **Make public**을 누르거나 **Project configuration → General → Visitor access → Project visibility**에서 프로덕션을 Public으로 바꿉니다. 무료 요금제의 Private 프로젝트는 친구들이 일반 링크만으로 접속할 수 없습니다. 계정 종류와 팀 설정에 따라 메뉴가 다를 수 있습니다.
6. Netlify가 새 무료 프로젝트에 **Powered by Netlify** 배지를 표시하는 경우, 이를 원하지 않으면 **Project configuration → General → Powered by Netlify badge**에서 꺼 주세요. 이 배지는 프로젝트 코드의 광고가 아니라 Netlify가 넣는 표시입니다.
7. 생성된 사이트 주소 뒤에 `/api/game`을 붙여 열었을 때 `{"ok":true,"service":"moa"}`가 나오면 함수 경로는 동작한 것입니다. 이 확인만으로 데이터 저장이나 6인 게임 전체가 검증되는 것은 아닙니다.
8. 서로 다른 휴대폰 두 대 이상에서 직접 방을 만들고, 다른 기기로 참가해 **게임 시작·턴 진행·새로고침 재접속**까지 확인합니다. 최종적으로 5~6명과 테스트해 주세요.

**중요:** `public` 폴더만 정적 사이트로 따로 업로드하거나 이전 Express/Socket.IO 버전 ZIP을 사용하면 게임 서버가 없어서 작동하지 않습니다. 위 GitHub 연결 방식으로 프로젝트 전체를 올려야 합니다.

[Netlify GitHub 연결 안내](https://docs.netlify.com/start/quickstarts/deploy-from-repository/) · [프로젝트 공개 설정](https://docs.netlify.com/manage/security/secure-access-to-sites/project-visibility/) · [Netlify 배지 끄기](https://docs.netlify.com/manage/projects/powered-by-netlify-badge/)

## 3. 친구들과 플레이하기

1. 방장이 사이트를 열고 **새 방 만들기**를 눌러 닉네임과 게임을 선택합니다.
2. 대기실의 초대 링크·QR 코드 또는 **8자리 방 코드**를 친구들에게 보냅니다.
3. 친구들이 각자 휴대폰에서 링크를 열어 닉네임을 입력합니다. 모두 모이면 방장이 게임을 시작합니다. 최대 6명입니다.
4. 같은 기기·같은 브라우저에서 같은 초대 링크를 다시 열면 원래 좌석으로 재접속합니다. 브라우저 데이터 삭제, 다른 브라우저, 아이폰의 홈 화면 앱처럼 별도 저장소를 쓰는 경우에는 좌석이 복구되지 않을 수 있습니다. 같은 브라우저의 여러 탭은 대개 같은 사람으로 인식됩니다.
5. 홈 화면에 추가하면 앱처럼 열 수 있습니다. 아이폰은 **Safari → 공유 → 홈 화면에 추가**, 안드로이드는 **Chrome 메뉴 → 앱 설치/홈 화면에 추가**를 사용하세요. 앱스토어 설치 앱은 아니며 게임 중 인터넷이 필요합니다.

방 코드를 아는 사람은 게임 시작 전에 들어올 수 있습니다. 로그인이나 별도 방 비밀번호가 없으므로 링크·코드를 지인에게만 공유하고 실명·전화번호 같은 개인정보를 넣지 마세요. GitHub 저장소를 Private으로 만들어도 **Public 사이트 주소 자체가 비공개가 되는 것은 아닙니다.** 검색 방지 설정은 보안 기능이 아닙니다.

## 게임과 판본 차이

### 타일 클럽 — 2~6명
- 같은 숫자·다른 색의 그룹이나 같은 색의 연속 숫자 3개 이상을 만듭니다. 처음에는 내 손패로 30점 이상을 등록하며, 이후 테이블의 조합을 바꿀 수 있습니다. 조커는 유효한 조합에 남아야 하고 새로 손패를 1개 이상 내야 합니다.
- 2~4인은 106장, 5~6인은 160장(조커 4장)을 사용하고 각자 14장으로 시작합니다. 손패 조커는 종료 시 30점으로 표시합니다.
- 이 앱은 **1분 제한과 시간 초과/미완성 벌칙을 자동 적용하지 않으며**, 여러 판의 누적 점수를 별도로 관리하지 않습니다. 더미가 소진된 뒤 모두 연속으로 넘기면 종료합니다. 첫 순서는 방 참가 순서입니다. 조커 회수 방식 등은 판본별로 차이가 있을 수 있습니다.

### 섬 개척 — 3~6명
- 3~4인 19칸, 5~6인 30칸 지도와 한정된 은행, 항구, 자원 생산·거래, 도둑, 건설, 발전 카드, 최장 길·최대 기사단을 사용합니다. 승리 목표는 10점입니다.
- **5~6인은 요청하신 예전 특별 건설 방식**입니다. 한 사람의 일반 차례가 끝나면 다른 사람들이 순서대로 건설·발전 카드 구매를 할 수 있습니다. 이때 교환과 발전 카드 사용은 할 수 없으며 실제로 건설·구매할 수 없는 사람은 자동으로 넘어갑니다. 최근 판본의 짝 차례 방식은 아닙니다.
- 지도 지형, 숫자와 항구는 앱에서 섞고 배치하므로 공식 판본의 고정 테두리·숫자 배치와 완전히 같지 않습니다. 첫 순서는 방 참가 순서입니다.

### 다이스 데이 — 2~6명
- 요트형 12칸 점수표를 씁니다. 1~6 합계 63점 이상은 보너스 35점, 풀하우스는 3개+2개의 눈 합, 4연속은 15점, 5연속은 30점, 요트는 50점입니다. 요트/야추는 판본마다 점수가 다를 수 있습니다.

각 게임의 **규칙** 버튼에서도 요약을 볼 수 있습니다. 상표·그래픽의 정식 라이선스를 받은 제품이 아닙니다. 개인 사용을 넘어 공개 배포하려면 관련 권리를 별도로 확인하세요.

## 비용과 운영상 주의

- 앱 자체의 광고·결제는 없지만, **호스팅과 통신까지 영구 무료라고 보장할 수는 없습니다.** Netlify의 요금제와 무료 한도를 직접 확인하세요. 무료 한도 초과 시 사이트가 일시 중단되거나, 유료 요금제에서는 설정에 따라 비용이 발생할 수 있습니다. 휴대폰 데이터 요금도 별도입니다.
- 참고로 크레딧 기반 Free 요금제는 현재 월 300크레딧이며, 프로덕션 배포·요청·함수 실행·데이터 전송 등이 한도를 사용합니다. 계정의 구형 요금제나 이후 정책은 다를 수 있습니다. [Netlify 크레딧 공식 안내](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/how-credits-work/)
- 눈에 보이는 게임 화면은 약 3초 간격으로 서버를 확인합니다. 6명이 계속 화면을 보고 있으면 동작·화면 열기 외에 시간당 약 7,200회의 상태 확인 요청이 생길 수 있습니다. 상황에 따라 지연·콜드 스타트가 있고, 다른 사용량까지 포함하면 실제 크레딧 소모는 달라집니다. Netlify 대시보드의 사용량을 살펴보세요.
- 게임 진행은 Netlify Blobs에 저장됩니다. 7일 동안 사용하지 않은 방은 재입장할 수 없지만 저장된 데이터가 물리적으로 자동 삭제되는 것은 아닙니다. 오래된 데이터는 Netlify Blobs 관리 화면에서 직접 정리할 수 있습니다. 재배포 시 같은 사이트의 방 데이터는 일반적으로 유지됩니다.
- 게임 도중 사람이 이탈하면 그 사람의 차례에서 기다릴 수 있습니다. 중간에 다른 사람으로 교체하거나 AI가 대신하지 않습니다. 같은 기기에서 재접속하거나 새 방을 만들어 주세요. 대기실에서는 방장이 참가자를 내보낼 수 있습니다.
- 인터넷 속도, Netlify 장애·요금제, 기기 및 브라우저 상태에 따라 연결이 끊기거나 게임이 중단될 수 있습니다. 모든 실물 휴대폰을 검증한 것은 아닙니다.

## 문제가 생기면

- **배포가 실패함:** Netlify의 Deploy log에서 오류를 확인합니다. GitHub 저장소 첫 화면에 `package.json`과 `netlify.toml`이 있는지, 빌드 명령이 `npm run build`인지 확인합니다.
- **화면은 뜨는데 방을 만들 수 없음:** `/api/game`의 응답과 Netlify의 Functions 로그를 확인합니다. 정적 파일만 올린 경우 전체 저장소를 연결해야 합니다. Netlify Functions와 Blobs 접근, 사이트 공개 상태 및 무료 한도를 확인합니다.
- **친구에게 Netlify 로그인 화면이 나옴:** 위의 프로젝트 Public 설정을 확인하세요. 저장소의 Private 설정과는 별개입니다.
- **재접속이 안 됨:** 이전에 참가한 동일한 기기·브라우저·사이트 주소에서 동일한 방 링크를 열어 보세요. 브라우저 데이터 삭제 등으로 좌석 정보가 사라졌거나 방이 만료되면 새 방을 만들어야 합니다.
- **로컬 Netlify Dev에서 상태 저장 오류:** 일부 Netlify Blobs 로컬 에뮬레이터 버전은 읽기 ETag와 원자적 조건부 쓰기를 제대로 흉내 내지 못합니다. 이 프로젝트는 안전하지 않은 무조건 덮어쓰기를 거부합니다. 아래 `npm run dev`는 테스트용 메모리 저장소를 사용합니다. 실제 Netlify 프로덕션은 별도로 확인해야 합니다.

## 개발자용 로컬 테스트

Node.js **22.12 이상**이 필요합니다.

```bash
npm ci
npm run build  # 필수 파일·함수 import·게임/저장소 테스트
npm run dev    # http://localhost:3001
```

`npm run dev`는 로컬 테스트 전용 메모리 저장소를 사용하므로 프로세스를 끄면 그 방이 사라집니다. 실제 Netlify Blobs나 배포 환경이 아닙니다. 브라우저 테스트는 브라우저를 설치하고 로컬 서버를 띄운 뒤 실행할 수 있습니다.

```bash
npx playwright install chromium webkit
npm run test:browser
```

게임 엔진·6인 동시 참가·중복 동작·좌석 비공개·조건부 쓰기 계약 등을 자동 테스트합니다. 일부 Netlify 로컬 에뮬레이터 결함을 보완한 개발 테스트와 모바일 화면 시뮬레이션도 수행했지만, 이 결과는 **실제 Netlify 운영 환경이나 실물 기기 테스트를 대신하지 않습니다.**
